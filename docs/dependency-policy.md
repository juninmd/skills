# Dependency review and protection

Dependency changes receive two complementary review results. `security-ops` checks the exact locked direct and transitive versions against fresh advisories, registry timestamps, integrity, and install/build hooks. `code-review` checks changed consumers against official changelogs and migration guides, including breaking behavior in patch or minor releases. `package-management` applies supported project-local controls and regenerates locks. `finishing-dev` requires these results before a clean PR-readiness claim.

The minimum publication age is **24 hours for the exact selected version**. A mature package can publish a compromised new version. Waiting reduces early-adoption exposure; it does not prove safety. Unknown metadata, an unavailable scanner, or incomplete coverage remains unverified. Stronger existing waits stay in place. Emergency exceptions need an explicit owner, version, reason, authority, and expiry.

## Repository enforcement

- `pnpm@10.34.5` is pinned for development, validation, and releases.
- `pnpm-workspace.yaml` sets `minimumReleaseAge: 1440` and `trustPolicy: no-downgrade`.
- `pnpm run dependencies:age` verifies all registry packages in the pnpm v9 lockfile against live public npm metadata, including exact publication timestamps and matching integrity. Unsupported sources, missing releases, and network failures fail the gate. It preserves a stricter configured wait and does not execute package hooks.
- `pnpm run dependencies:audit` includes development dependencies. Validation and release workflows run both gates after an install with scripts disabled.
- Dependabot version updates wait seven days. Its cooldown does not cover security updates or manual installs; those still encounter the repository gates.

The registry check uses at most six concurrent requests, a 15-second request timeout, and a 120-second overall deadline. Responses are capped at 64 MiB because the official Vite metadata currently exceeds 37 MiB. It does not accept redirects or reuse stale scan results. This check covers this repository's public npm lockfile; other registries and ecosystems require their own detected-stack procedure.

```bash
pnpm install --frozen-lockfile --ignore-scripts
pnpm run dependencies:check
pnpm run validate
pnpm run docs:build
```

## Current remediation and compatibility

The baseline audit reported ten advisories across Vite/esbuild, PostCSS, nanoid, source-map-js, and Vue server rendering. Scoped overrides select patched releases: Vite `6.4.3`, PostCSS `8.5.23`, nanoid `3.3.18`, source-map-js `1.2.2`, and Vue/shared `3.5.42`. Vite's esbuild dependency resolves in its patched `0.25` line. Locks are generated by pnpm rather than edited by hand.

The Vite override crosses from `5.4.21` to `6.4.3`. The installed plugin Vue `5.2.4` declares Vite 5 and 6 peers. The [Vite 6 migration guide](https://v6.vite.dev/guide/migration) describes changes to conditions, Sass, PostCSS loading, and experimental runtime APIs; this repository does not customize those options. Validation must cover the actual VitePress build and local dev rendering rather than assume peer compatibility proves execution. The unchanged VitePress release remains `1.6.4`.

Follow official [pnpm resolution settings](https://pnpm.io/settings/dependency-resolution), [uv cooldown semantics](https://docs.astral.sh/uv/concepts/resolution/#dependency-cooldowns), and [Dependabot cooldown rules](https://docs.github.com/en/code-security/reference/supply-chain-security/dependabot-options-reference#cooldown). Enable only controls supported by the detected manager; do not invent npm, pip, or Cargo age flags.

Rollback restores the prior workspace configuration and lockfile together, then reinstalls in frozen mode. That also restores known vulnerable versions, so keep affected development servers isolated while choosing an alternative fix.
