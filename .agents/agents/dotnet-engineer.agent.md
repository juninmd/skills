## Guidelines

### Code Design Rules
- ✅ Use `ArgumentNullException.ThrowIfNull(x)` for null validation; `string.IsNullOrWhiteSpace(x)` for strings
- ✅ Guard early; fail fast on invalid inputs
- ✅ Choose precise exception types (`ArgumentException`, `InvalidOperationException`), never base `Exception`
- ✅ Don't swallow errors; log and rethrow or let them bubble
- ✅ Don't add interfaces/abstractions unless used for external dependencies or testing
- ✅ Don't edit auto-generated code (`*.g.cs`, `// <auto-generated>`)
- ✅ Keep names consistent; pick one style and stick to it
- ✅ Comments explain why, not what
- ✅ Reuse existing methods and patterns
- ✅ Use file-scoped namespaces, raw strings, switch expressions, ranges/indices when TFM allows

### Async/Await Best Practices
- ✅ All async methods end with `Async` suffix
- ✅ Always `await`; no fire-and-forget tasks
- ✅ Cancellation tokens end-to-end: accept `CancellationToken`, pass through, `ThrowIfCancellationRequested()` in loops
- ✅ Use linked `CancellationTokenSource` with `CancelAfter` for timeouts
- ✅ `ConfigureAwait(false)` in library/helper code; omit in app entry points
- ✅ Stream JSON: `GetAsync(..., ResponseHeadersRead)` → `ReadAsStreamAsync` → `JsonDocument.ParseAsync`
- ✅ Never `async/await` if just returning the task (no `await` needed)
- ✅ Return non-zero exit code on cancellation (e.g., `130`)
- ✅ Prefer `Task` over `ValueTask` unless measured to help

### Performance & Resource Management
- ✅ Simple first; optimize measured hot paths
- ✅ Stream large payloads; avoid extra allocations
- ✅ Use `Span<T>`, `Memory<T>`, pooling when optimization matters
- ✅ Async end-to-end; no sync-over-async anti-patterns
- ✅ Use dependency injection; avoid static fields and singletons
- ✅ Lazy initialization for expensive resources

### Security
- ✅ Enable nullable reference types: `<Nullable>enable</Nullable>`
- ✅ Validate all user inputs; sanitize before use
- ✅ Use secured secrets management (Azure Key Vault, etc.)
- ✅ Move user-facing strings into resource files for localization
- ✅ Implement proper authentication and authorization
- ✅ Encrypt sensitive data; hash passwords properly
- ✅ Never log sensitive information

## Testing Best Practices

### Test Structure
- ✅ Separate test project: `[ProjectName].Tests`
- ✅ Mirror class structure: `CatDoor` → `CatDoorTests`
- ✅ Name by behavior: `WhenCatMeowsThenCatDoorOpens()`
- ✅ Use public instance classes; avoid static fields
- ✅ No branching/conditionals inside tests
- ✅ One behavior per test; multiple tests for multiple outcomes

### Unit Tests
- ✅ Arrange-Act-Assert (AAA) pattern
- ✅ Clear assertions verifying test name's outcome
- ✅ Avoid Unicode symbols
- ✅ Test through public APIs; don't change visibility
- ✅ Require tests for new/changed public APIs
- ✅ Assert specific values and edge cases, not vague outcomes
- ✅ Avoid disk I/O; if needed, randomize paths, don't clean up

### Frameworks
- **xUnit**: Use `[Fact]` or `[Theory]` with `[InlineData]`; setup/teardown via constructor and `IDisposable`
- **NUnit**: Use `[TestFixture]` and `[Test]`; `[TestCase]` for parameterization
- **MSTest**: Use `[TestClass]` and `[TestMethod]`; `[TestInitialize]`/`[TestCleanup]`

### Mocking
- ✅ Avoid mocks if possible; test through public APIs
- ✅ Mock external dependencies only; never mock code under test
- ✅ Verify mock behavior matches real dependency
