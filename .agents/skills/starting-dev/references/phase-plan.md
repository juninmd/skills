# Plan procedure
Owned and executed by `starting-dev`; this file is not a standalone skill.

1. Read the request, research, selected prototype if any, and actual repository constraints.
2. Batch only unanswered material questions. Existing user direction remains authoritative; do not require reconfirmation to advance.
3. Resolve module boundaries and contracts through `software-architecture` when needed. Keep scope and non-goals explicit.
4. Create `plan.md`: goal, acceptance criteria, files, ordered vertical slices, dependencies, risk/rollback, and exact verification commands with expected results. Use `requirements-planning`'s incremental delivery and spec templates procedures when appropriate.
5. Explain any acceptance criterion added, replaced, or deferred from research. Do not silently drop a user requirement.
6. Track externally only when requested and authorized. Start implementation when the plan is actionable; a separate approval gate exists only for a real missing user decision or action authority.

A verification command must exist in the repo or be intentionally implemented. An estimate is not a guarantee. Update the state after the plan is written and record any bypassed stage and rationale.
