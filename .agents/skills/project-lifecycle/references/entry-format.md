# Entry Format and Tag Vocabulary

## Filename

```
TYPE-YYYYMMDD-NNN-tag1-tag2.md
error-20260824-001-nestjs-testing.md
learning-20260824-002-pnpm-ci.md
missing-20260824-003-observability.md
```

- `TYPE` is one of `learning`, `error`, `missing`.
- `NNN` increments per day, zero-padded.
- One to three tags, lowercase, hyphen-separated, taken from the vocabulary below.

Tags live in the filename so recall filters with a directory listing instead of reading every entry. That is the whole point of the convention: `ls .learnings/*-nestjs-*` costs nothing, opening twenty files costs a context window.

## Template

Every entry is exactly these four fields, 15 lines total, hard ceiling.

```markdown
---
tags: [nestjs, testing]
---
**Symptom** — what was observed, in one line, in the words it would be searched by.
**Cause** — the actual mechanism, not the guess that preceded it.
**Fix** — the concrete change, with the command or code shape that worked.
**Applies when** — the conditions under which this is true. Version, framework, OS, configuration.
```

Duplicating the tags in frontmatter is optional; the filename is authoritative. Add frontmatter only if tooling reads it.

### Field rules

- **Symptom**: the error text, the failing behavior, the observable. Written so a future search finds it. No narrative.
- **Cause**: one line. If you cannot state the mechanism, the entry is not ready — a workaround with an unknown cause is still worth recording, but say so explicitly ("cause unconfirmed").
- **Fix**: the smallest reproducible action. A command, a config line, a code shape. Not "we refactored the module".
- **Applies when**: the scoping field, and the one most often skipped. Without it an entry gets applied where it is wrong. Name versions and platform; on this repository that includes Windows and PowerShell where the fix is shell-specific.

### Example

```markdown
---
tags: [pnpm, ci]
---
**Symptom** — `ERR_PNPM_OUTDATED_LOCKFILE` in CI, install passes locally.
**Cause** — the lockfile was regenerated by a different pnpm major than the CI image pins.
**Fix** — pin `packageManager` in `package.json` and let CI honor it via corepack.
**Applies when** — pnpm 8+, `--frozen-lockfile` in CI, contributors on mixed pnpm versions.
```

## Tag vocabulary

Keep the list short; an unbounded vocabulary filters nothing. Extend it deliberately and record additions here.

- Stack: `node`, `python`, `dotnet`, `go`, `rust`, `sql`
- Framework: `nestjs`, `fastapi`, `react`, `next`, `vite`
- Concern: `testing`, `build`, `ci`, `deploy`, `docker`, `k8s`, `perf`, `security`, `auth`, `observability`
- Environment: `windows`, `powershell`, `wsl`, `macos`, `linux`
- Process: `review`, `git`, `docs`, `tooling`

## What does not belong in an entry

- Session transcript, reasoning chains, or narrative of how the answer was reached.
- Anything a reader could get from the code or the official documentation in one look.
- Secrets, credentials, tokens, internal hostnames, or client names — unconditionally when `.learnings/` is committed, and as a default habit when it is ignored.
- Restatements of an existing entry. Update the existing one instead; the count cap is a budget, not a suggestion.
