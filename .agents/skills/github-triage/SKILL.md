# GitHub Issue Triage

Expert methodology for managing the issue lifecycle using a structured state machine and the `gh` CLI.

## State machine

| Category | State |
|---|---|
| `bug` | `needs-triage` → `needs-info` / `ready-for-agent` / `ready-for-human` / `wontfix` |
| `enhancement` | `needs-triage` → `needs-info` / `ready-for-agent` / `ready-for-human` / `wontfix` |

Every issue must have **exactly one category label** and **exactly one state label**. Flag conflicts before proceeding.

## Workflow steps

### 1. Gather context

- Read the full issue body and all comments.
- Read all files in `.out-of-scope/` — match by **concept similarity**, not keyword.
- If a match exists, surface it: *"This is similar to `.out-of-scope/dark-mode.md` — we rejected this before because [reason]. Do you still feel the same way?"*

### 2. Recommend category and state

Present recommendation with reasoning. Don't proceed without maintainer confirmation on the category.

### 3. Reproduce bugs

Attempt a **non-destructive** reproduction before setting `ready-for-agent` on a bug. If reproduction fails, set `needs-info` with a template capturing what was established and what's needed.

### 4. Apply outcome

| Outcome | Action |
|---|---|
| `ready-for-agent` | Post an agent brief (see [AGENT-BRIEF.md](references/AGENT-BRIEF.md)) |
| `ready-for-human` | Explain why human involvement is needed |
| `needs-info` | Post a template with established facts + specific questions |
| `wontfix` (bug) | Polite explanation, then close |
| `wontfix` (enhancement) | Document in `.out-of-scope/`, link in comment, close (see [OUT-OF-SCOPE.md](references/OUT-OF-SCOPE.md)) |

## Mandatory disclaimer

All AI-generated public comments must include:
> *This was generated by AI during triage.*

## Core Principles

1. **Disclaimer:** Every public comment must include the AI disclaimer.
2. **State Integrity:** Exactly one state label and one category label at all times.
3. **Safety:** Reproduction attempts must be non-destructive.
4. **Durability:** Agent briefs must not reference file paths or line numbers.

## Checklist

- [ ] Read all prior triage notes and `.out-of-scope/` before proposing steps.
- [ ] Match by concept similarity when checking out-of-scope.
- [ ] Provide clear recommendations with reasoning.
- [ ] Confirm all label changes and comments with maintainer.
- [ ] Agent briefs follow the template in [AGENT-BRIEF.md](references/AGENT-BRIEF.md).
