# Triage

Platform-agnostic issue triage using a structured state machine.

## State machine

**Categories:** `bug` | `enhancement`

**States:** `needs-info` | `ready-for-agent` | `ready-for-human` | `wontfix`

Every issue gets exactly one category and one state.

## Workflow

### 1. Gather context

- Read the full issue description and any prior comments or context.
- Check any `.out-of-scope/` directory or equivalent — match by **concept similarity**.
- If a prior rejection matches, surface it before proceeding.

### 2. Classify

Determine category:
- **bug** — something is broken; expected behavior differs from actual behavior
- **enhancement** — new capability or improvement to existing behavior

Determine state:
- **needs-info** — not enough information to proceed (describe what's established and what's needed)
- **ready-for-agent** — fully specified, reproducible, can be handed to an AFK agent
- **ready-for-human** — requires human judgment or access
- **wontfix** — out of scope, duplicate, or won't be addressed

### 3. Reproduce bugs

For bugs targeting `ready-for-agent`: attempt a non-destructive reproduction first. If reproduction fails, move to `needs-info` with a structured summary.

### 4. Apply outcome

| State | Action |
|---|---|
| `ready-for-agent` | Write an agent brief: current behavior, desired behavior, key interfaces, acceptance criteria, out of scope |
| `ready-for-human` | Explain specifically why human involvement is needed |
| `needs-info` | List what is established + specific questions needed |
| `wontfix` | Explain the decision; for enhancements, document in `.out-of-scope/` if a knowledge base exists |

## Agent brief format

```
**Category:** bug / enhancement
**Summary:** one-line description

**Current behavior:** [what happens now]
**Desired behavior:** [what should happen — include edge cases]

**Key interfaces:**
- [Type or function that needs to change]

**Acceptance criteria:**
- [ ] Testable criterion 1
- [ ] Testable criterion 2

**Out of scope:**
- [What NOT to change]
```

Rules:
- No file paths — they go stale
- No line numbers
- Describe behavior, not procedure

## Note on AI-generated content

If posting to a public tracker, include:
> *This was generated by AI during triage.*

## Checklist

- [ ] Context read including any out-of-scope knowledge base.
- [ ] Out-of-scope checked by concept similarity before classifying.
- [ ] Exactly one category and one state assigned.
- [ ] Bug reproduction attempted before setting `ready-for-agent`.
- [ ] Agent brief includes current/desired behavior, interfaces, acceptance criteria, and out of scope.
- [ ] AI disclaimer included in any public comment.
