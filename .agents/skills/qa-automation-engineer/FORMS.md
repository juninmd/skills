# QA Automation Engineer Forms

## 1. Test Automation Plan (test_plan.md)

### Goal
Define the strategy for automating a specific feature or user flow.

### Fields
- **Feature Name:** [Feature Title]
- **Target Environment:** [Staging/UAT/Local]
- **Framework:** [Playwright/Cypress/Selenium]
- **User Journeys:**
    - **Journey 1:** [Description of flow]
    - **Journey 2:** ...
- **Test Data Requirements:** [What data is needed?]
- **Selectors Strategy:** [e.g., Use data-testid exclusively]

## 2. Bug Report (bug_report.md)

### Goal
Document a defect identified during automated or manual testing.

### Fields
- **Title:** [Concise summary of the issue]
- **Severity:** [Blocker/Critical/Major/Minor]
- **Environment:** [Browser, OS, Version]
- **Steps to Reproduce:**
    1. [Step 1]
    2. [Step 2]
- **Expected Result:** [What should happen?]
- **Actual Result:** [What actually happened?]
- **Artifacts:** [Links to screenshots, videos, or trace files]
- **Automated Test ID:** [If applicable, the ID of the failing test]

## 3. Test Execution Summary (test_summary.md)

### Goal
Summarize the results of a test suite execution.

### Fields
- **Suite Name:** [Name of the test suite]
- **Execution Date:** [Timestamp]
- **Total Tests:** [Count]
- **Passed:** [Count]
- **Failed:** [Count]
- **Skipped:** [Count]
- **Duration:** [Time taken]
- **Failure Analysis:** [Brief explanation of why tests failed]
